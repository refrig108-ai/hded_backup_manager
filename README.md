# HDED Backup Manager 0.4.2

مدير النسخ الاحتياطي لـ ERPNext 16 وFrappe 16.

## المزايا
- النسخ الاحتياطي باستخدام Bench الرسمي.
- نسخ قاعدة بيانات الموقع فقط في ملف SQL مضغوط واحد.
- لا ينسخ مجلدات التطبيقات أو الملفات العامة والخاصة أو المرفقات.
- فحص سلامة النسخ.
- جدولة يومية وأسبوعية وشهرية.
- إدارة الاحتفاظ بالنسخ.
- استعراض الأقراص الداخلية والخارجية المركّبة على خادم Ubuntu واختيار مجلد الحفظ بالنقر.
- نمط نسخ دوري مجدول أو نسخة واحدة فقط عند الطلب؛ بعد اكتمال النسخة الواحدة يمنع التطبيق تكرارها بهذا النمط.
- فحص المجلد والصلاحيات والمساحة المتاحة والتحقق من اتصال القرص الخارجي عند اشتراطه.
- الإبقاء على النسخ القديمة ظاهرة بعد تغيير مسار التخزين.
- واجهة عربية محمية بدور System Manager.
- ربط Google Drive عبر OAuth 2.0 مع حفظ الأسرار والرموز مشفّرة على الخادم.
- رفع ملف قاعدة البيانات إلى Google Drive بعد نجاح النسخة المحلية مع رفع قابل للاستئناف وقائمة انتظار لإعادة المحاولة.
- استعراض نسخ Google Drive واستعادة قاعدة البيانات منها بعد إنشاء نسخة أمان محلية.

## المتطلبات
- Ubuntu أو Linux مع systemd.
- Frappe 16 وERPNext 16.
- Bench وبيئة Python باسم env.
- مستخدم Linux يشغّل Bench.

## التثبيت

تنزيل التطبيق:

    bench get-app --branch feature/local-backup-path-0.3.0 https://github.com/refrig108-ai/hded_backup_manager.git

تثبيته على الموقع:

    bench --site YOUR_SITE install-app hded_backup_manager

تثبيت خدمة النسخ:

    sudo bash apps/hded_backup_manager/scripts/install_systemd.sh --bench-dir "$PWD" --site YOUR_SITE --user YOUR_LINUX_USER

استبدل YOUR_SITE باسم الموقع وYOUR_LINUX_USER بمستخدم Linux.

إذا كان مؤقت HDED موجوداً مسبقاً، يحافظ المثبت على جدولته وحالته الحالية. عند التثبيت الجديد ينشئ المثبت ملفات الخدمة والمؤقت فقط ويترك المؤقت متوقفاً؛ لا يبدأ النسخ الدوري تلقائياً ولا يعتمد الساعة 02:00 كموعد تشغيل. افتح صفحة مدير النسخ الاحتياطي واختر مواعيد النسخ ثم احفظها لتفعيل المؤقت. إعدادات الموقع الجديدة تبدأ وكل مواعيد النسخ فيها معطّلة.

## المنطقة الزمنية

    sudo timedatectl set-timezone Asia/Aden

## صفحة التطبيق

    /app/backup-manager

## التحقق من الخدمة

    sudo /usr/local/sbin/hded-backup-control status
    systemctl list-timers hded-erp-backup.timer --all
    journalctl -u hded-erp-backup.service -n 100 --no-pager

## التحديث

    git -C apps/hded_backup_manager pull --ff-only
    ./env/bin/python -m pip install --no-deps --no-build-isolation -e apps/hded_backup_manager
    bench build --app hded_backup_manager
    bench --site YOUR_SITE clear-cache
    sudo supervisorctl restart 'medical-erp16-bench-web:*'

## إزالة خدمات النظام

    sudo bash apps/hded_backup_manager/scripts/uninstall_systemd.sh

الإزالة لا تحذف ملفات النسخ الاحتياطية أو إعدادات الموقع.

## التخزين المحلي

من زر «استعراض الأقراص والمجلدات» يمكن اختيار وحدة التخزين ثم التنقل إلى المجلد المطلوب على خادم Ubuntu. يمكن أيضاً إدخال مسار مطلق يدوياً. يمكن ترك المسار فارغاً لاستخدام المسار الافتراضي داخل مجلد الموقع، أو إدخال مسار مثل:

    /mnt/backup-drive/hded-backups

عند اختيار قرص خارجي، فعّل خيار اشتراط وجود وحدة تخزين منفصلة. سيوقف مدير النسخ عملية النسخ إذا لم يكن القرص مركباً، حتى لا تُكتب النسخ بالخطأ على قرص النظام. أدخل مجلداً فرعياً داخل نقطة التركيب، ولا تختَر نقطة تركيب القرص نفسها. تغيير المسار لا ينقل النسخ القديمة ولا يحذفها؛ يحتفظ التطبيق بسجل لمسارات التخزين السابقة ويعرض النسخ الموجودة فيها تحت تسمية "مجلد سابق". سياسة الاحتفاظ تطبق على المسار النشط فقط.

يجب أن يكون مجلد التخزين آمناً بصلاحيات المالك فقط (0700)، وأن يكون قابلاً للكتابة بواسطة مستخدم خدمات ERPNext. عند اختيار وحدة تخزين منفصلة، يُفعّل التطبيق اشتراط بقاء وحدة التخزين مركّبة حتى لا يكتب النسخ إلى قرص النظام عند فصلها.

### نمط النسخ

- **نسخ دوري تلقائي:** ينفذ النظام النسخ في المواعيد اليومية أو الأسبوعية أو الشهرية المحددة، ويضع النسخ المتتابعة في مجلد التخزين نفسه.
- **نسخة واحدة فقط:** يوقف التطبيق مؤقت النسخ التلقائي، ويسمح بتشغيل نسخة يدوية واحدة. بعد نجاحها، يحفظ وقتها ومعرّفها ويمنع أي تشغيل آخر حتى تغيّر النمط وتحفظ الإعدادات من جديد.

## مجلد Windows عبر VirtualBox

حتى يحفظ ERPNext النسخ مباشرةً على قرص Windows المضيف، أنشئ مجلداً مثل `D:\HDED_Backups` على Windows، ثم أضفه في إعدادات الآلة الافتراضية من:

`VirtualBox Manager → اختر الآلة → Settings → Shared Folders → Add`

اختر مسار المجلد، واكتب اسم مشاركة بسيطاً مثل `HDED_Backups`، وفعّل `Auto-mount` و`Make Permanent`، واترك `Read-only` غير محدد. مع Guest Additions، يظهر المجلد عادةً في Ubuntu داخل `/media/sf_HDED_Backups`.

يجب أن يكون مستخدم Ubuntu الذي يشغّل ERPNext عضواً في مجموعة `vboxsf` ليتمكن من القراءة والكتابة. يمكن فحص ذلك بالأمرين:

    findmnt -t vboxsf
    id mohammed

إذا كانت مجموعة `vboxsf` موجودة والمستخدم ليس عضواً فيها:

    sudo usermod -aG vboxsf mohammed

بعد تعديل المجموعة، سجّل الخروج من Ubuntu وادخل مجدداً أو أعد تشغيل الآلة الافتراضية. ثم افتح مستعرض التخزين في التطبيق، واختر المشاركة نفسها أو مجلداً بداخلها. سيستخدم التطبيق مسار Ubuntu المركّب، بينما تُكتب الملفات فعلياً في مجلد Windows المضيف. المسار الأصلي على Windows تحدده إعدادات VirtualBox، ولا يستطيع ضيف Ubuntu استعراض أقراص Windows غير المشاركة.

## Google Drive

يدعم الإصدار 0.4.0 ربط Google Drive لحفظ **ملفات قاعدة البيانات المضغوطة فقط**.

### إعداد OAuth مرة واحدة

1. افتح [Google Cloud Console](https://console.cloud.google.com/apis/credentials)، وأنشئ مشروعاً أو اختر مشروعاً قائماً.
2. فعّل **Google Drive API**.
3. جهّز شاشة موافقة OAuth، ثم أنشئ OAuth Client ID من نوع **Web application**.
4. إذا كان نوع المستخدم External، أضف حساب Google المستخدم إلى Test users أثناء التجربة.
5. استخدم عنوان إعادة التوجيه المعروض في صفحة مدير النسخ، وأضفه حرفياً إلى **Authorized redirect URIs** في Google Cloud.
6. أدخل Client ID وClient Secret وعنوان إعادة التوجيه في صفحة «التخزين والربط الخارجي»، ثم احفظ الإعدادات واضغط «ربط حساب Google».
7. بعد العودة إلى ERPNext، اختبر الاتصال. يهيئ التطبيق مجلد **HDED ERP Backups** تلقائياً عند أول اختبار أو رفع.

قبل الاعتماد على النسخ المجدولة، انقل شاشة موافقة OAuth إلى **In production**. توضح Google أن refresh tokens لتطبيق External في حالة Testing تنتهي بعد 7 أيام، وهذا يعطل الرفع التلقائي حتى إعادة التفويض. يجب أن يكون عنوان إعادة التوجيه HTTPS بنطاق صالح ومسجل في Google Cloud، وأن تكون الخدمة قابلة للوصول من متصفح المستخدم ومن Google. عنوان الشبكة الداخلي مثل `http://hded.erp` لا يصلح. لا تستخدم عنوان IP خاماً أو نطاقاً محلياً؛ يجب تجهيز اسم نطاق صالح وشهادة TLS موثوقة وربطه بخادم ERPNext قبل OAuth. عنوان إعادة التوجيه يجب أن يطابق المسار المعروض حرفياً.

### الرفع والاستعادة

- عند تفعيل «رفع النسخ الجديدة تلقائياً»، يرفع التطبيق ملف `*-database.sql.gz` بعد اكتمال النسخة المحلية وفقط بعد التحقق من وجود الملف.
- فشل الإنترنت لا يُفشل النسخة المحلية. يُسجل الملف في قائمة انتظار داخل مجلد `private` للموقع، وتتم محاولة رفعه مجدداً عند النسخ التالي أو من زر «إعادة رفع النسخ المعلقة».
- يستخدم الرفع جلسات Google Drive القابلة للاستئناف، ويتحقق التطبيق من اسم الملف والحجم وبصمة SHA-256.
- تعرض الصفحة النسخ الموجودة في مجلد HDED الخاص بالموقع، وتتيح استعادة قاعدة البيانات من نسخة مختارة.
- قبل الاستعادة من Drive، ينزل التطبيق الملف إلى مجلد مؤقت محمي، ويفحص الحجم والبصمة والضغط وتوافق إصدار Frappe، ثم ينشئ نسخة أمان محلية قبل استبدال قاعدة البيانات.
- الاستعادة من Drive تخص قاعدة البيانات فقط؛ لا تستعيد المرفقات أو ملفات الموقع أو إعداداته أو مصادر التطبيقات.

يستخدم التطبيق نطاق Google `drive.file` المحدود، وينشئ المجلد والملفات التي يديرها بنفسه. لا يطلب صلاحية قراءة جميع ملفات Drive.

### حماية بيانات الربط

تُحفظ بيانات Client Secret وRefresh Token مشفّرة باستخدام مفتاح تشفير الموقع في ملف `sites/YOUR_SITE/private/hded_backup_manager_google_drive.json` بصلاحيات مقيدة. لا تُرسل هذه البيانات إلى GitHub ولا تضعها في المحادثات أو السجلات. حافظ على نسخة آمنة من `site_config.json` ومفتاح `encryption_key`؛ فقد تحتاج إليه لفك تشفير بيانات OAuth بعد استعادة الموقع أو نقله.

OneDrive غير مفعّل في هذا الإصدار. البريد يستخدم نموذج Email Account القياسي في ERPNext.

## استعادة قاعدة البيانات

من جدول النسخ المحفوظة اختر «استعادة قاعدة البيانات» بجانب النسخة المطلوبة. قبل الاستبدال:

1. يفحص التطبيق ملف SQL المضغوط ويتأكد من سلامته ومن أنه ليس نسخة جزئية أو نسخة من إصدار Frappe أحدث.
2. يفعّل وضع الصيانة مؤقتاً.
3. ينشئ نسخة أمان من قاعدة البيانات الحالية داخل `sites/YOUR_SITE/private/restore_safety/`.
4. يستعيد قاعدة البيانات المختارة، ثم يمسح الذاكرة المؤقتة ويعيد الموقع إلى وضع التشغيل.
5. إذا فشلت الاستعادة بعد إنشاء نسخة الأمان، يحاول إعادة قاعدة البيانات السابقة تلقائياً. إذا فشل الرجوع أيضاً، يبقى وضع الصيانة مفعلاً لحماية الموقع وتظهر الحالة الحرجة في صفحة المدير.

الاستعادة تخص قاعدة البيانات فقط. لا تستعيد الصور أو المرفقات أو الملفات العامة والخاصة أو `site_config.json` أو مصادر التطبيقات. النسخ القديمة متعددة الملفات يمكن استخدامها لاستعادة قاعدة البيانات الموجودة بداخلها، لكن بقية ملفاتها لا تُستعاد من هذه الواجهة. لا تختَر نسخة من إصدار أحدث من Frappe الحالي.

## الأمان

لا ترفع ملفات النسخ الاحتياطية أو إعدادات المواقع أو مفاتيح الوصول إلى GitHub.


## نطاق النسخ الحالي

كل تشغيل جديد ينشئ ملفاً واحداً فقط: `TIMESTAMP-SITE-database.sql.gz`. لا يتم تضمين ملفات الموقع العامة أو الخاصة أو المرفقات أو ملفات إعدادات الموقع أو مصادر التطبيقات. تبقى النسخ القديمة متعددة الملفات كما هي ولا يحذفها التحديث. لا تدخل النسخ القديمة متعددة الملفات في سياسة الاحتفاظ الجديدة.
